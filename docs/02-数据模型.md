> **文档性质**：契约定义。定义会话三原语、划词引用、持久化表结构、自定义模型与配置文件。

## 1. 标识符与术语

```ts
type CourseId = string      // catalog v2 的稳定课程 ID，如 '南京大学-操作系统原理'
type DocumentId = string    // 仓库内相对路径，如 '计算机/计算机基础/操作系统/南京大学-操作系统原理/textbooks/模块01_…_精读全书.md'
```

两者都是 **`string` 别名，不是 branded type**——它们要参与持久化键、URL 拼装、日志，加 brand 只会在每个边界都要 cast。**URL 编码只在 `ContentSource` 实现内部发生**，其它地方一律用原始字符串。

**术语（避免同一个词指两级，见 `03` §1.4）**：

| 词 | 含义 |
|---|---|
| **册**（volume） | 一个 `模块XX_<册名>_精读全书.md`，含若干章。**标识符是 `documentId`** |
| **章**（chapter） | 册内的 H2，**就是流水线里的一篇「模块长文」**。序号是 `chapterIndex` |
| **笔记**（note） | `notes/笔记XX_…_笔记.md`。也是 document，只是 `kind` 不同 |
| 逐字稿（subtitle） | `subtitles/*.txt` 或块级 `subtitles/BLKxx_*.md`。**不提供阅读视图** |

`volume` 只作为**枚举值**出现（`DocumentSummary.kind`），实体标识一律用 `documentId`。

## 2. 会话三原语

无 wire 编码——不再需要 JSON-RPC / SSE 编解码（见 `00` §2.1）。流式是**同进程内的 async iterator**。

### 2.1 Item

```ts
type ItemStatus = 'started' | 'streaming' | 'completed' | 'failed'

type ItemBase = {
  id: string
  threadId: string
  turnId: string
  status: ItemStatus
  createdAt: number
  seq: number            // 同一 turn 内的顺序号
}

type UserMessageItem = ItemBase & {
  kind: 'user'
  text: string
  /** 本轮附件。**不透明**：核心只负责持久化、回放、原样传给 context 贡献点，从不解释其内容 */
  attachments?: MessageAttachment[]
}

type AssistantMessageItem = ItemBase & {
  kind: 'assistant'
  text: string
  reasoning?: string     // 部分模型返回的思维链，可选展示
  usage?: Usage          // 见 §5
  /** 失败时填；行为表见 04 §5.4。有 error 时 text 保留已流出的部分 */
  error?: {
    kind: 'network' | 'http' | 'aborted' | 'timeout'
    message: string
    status?: number      // kind === 'http' 时的状态码
  }
}

type ToolCallItem = ItemBase & {
  kind: 'tool-call'
  toolName: string
  args: unknown
}

type ToolResultItem = ItemBase & {
  kind: 'tool-result'
  toolName: string
  ok: boolean            // false = 工具返回 kind:'error' 或抛了异常（01 §4.1）
  text: string
}

type Item = UserMessageItem | AssistantMessageItem | ToolCallItem | ToolResultItem

/** 附件的通用容器。`kind` 的取值与 `data` 的形状**由插件定义**（v1 学习模块用 'quote'） */
type MessageAttachment = { kind: string; data: unknown }
```

**为什么附件是不透明的（与 §2.3 的 `Thread.binding` 同一个道理）**：v1 曾把 `quotes: QuoteRef[]` 与 `skillId?: string` 直接写在核心 `Item` 上——那是**和 `Thread` 硬编码册/章字段同一类的错误**。`QuoteRef` 属 `plugins/study`（§3），核心引用它会让 `packages/agent` 依赖 `plugins/study`，删掉 `plugins/` 后编译失败（`00` 不变量 4）。

| 层 | 谁负责 |
|---|---|
| 核心 | 只认 `attachments: { kind: string; data: unknown }[]`：持久化、回放、原样交给 `ContextContribution.provide`（`01` §2.5） |
| 插件 | 定义 `kind` 的取值与 `data` 的形状，在 `context` 贡献点里自己过滤并解释 |

**v1 学习模块的具体取值**（示范，写在这里而不是核心类型里）：`[{ kind: 'quote', data: <QuoteRef> }, { kind: 'capability', data: { id: 'explain' } }]`。

**纪律**：`createdAt` / `status` / `error` 属于**记录**，不属于上下文。组装请求时只取 `text` / `attachments` / `toolName` / `args`——**时间戳与状态绝不允许进入前缀区**（`04` §2.2 规则 1）。

### 2.2 Turn

```ts
type Turn = {
  id: string
  threadId: string
  status: 'running' | 'completed' | 'failed' | 'aborted'
  inputItemId: string
  startedAt: number
  endedAt?: number
}
```

### 2.3 Thread —— **核心不解释业务字段**

```ts
type Thread = {
  id: string
  title: string                    // 展示用
  /** 会话范围，由插件定义。核心只把它当作一个键 */
  scope: { kind: string; key: string }
  /** 插件自己的绑定数据。**核心从不读取、不解释它的内容** */
  binding: Record<string, unknown>
  modelRef?: string                // 指向某条自定义模型的 id
  createdAt: number
  updatedAt: number
  /** 内容改版检测（§2.4）。打开该册时比对得出，不参与前缀 */
  staleAt?: number
}
```

**为什么 `scope` 是开放的 `{ kind: string; key: string }` 而不是 `'chapter' | 'volume'`**：

`00` §1.3 定下「**核心不得硬编码任何业务语义**」，`00` §0.2 又定「后面还会扩展其他任务」。而 v1 把 `courseId` / `documentId` / `chapterIndex` / `chapterTitle` 直接写在 `Thread` 上——那等于把「学习模块的会话长什么样」焊进核心。第二个任务（例如命理排盘，按出生时刻+盘型组织会话）就**无法在不改核心类型的情况下**表达自己的会话范围。

定案：

| 层 | 谁负责 |
|---|---|
| `scope.kind` / `scope.key` | **插件**决定取值与语义。核心只用它做「同一范围复用同一线程」的查找 |
| `binding` | **插件**放自己的字段。核心把它当不透明对象存取 |
| 核心 | 只认 `id / title / scope / binding / modelRef / createdAt / updatedAt / staleAt` |

**v1 学习模块的具体取值**（作为示范，写在这里而不是核心类型里）：

| 会话 | `scope` | `binding` |
|---|---|---|
| 章会话（主） | `{ kind: 'chapter', key: '<documentId>#<chapterIndex>' }` | `{ courseId, documentId, chapterIndex, chapterTitle }` |
| 册会话（辅） | `{ kind: 'volume', key: '<documentId>' }` | `{ courseId, documentId }` |

插件用一个自己的类型化访问器读 `binding`（如 `readChapterBinding(thread)`），核心不参与。

**「一章一会话」这条规则因此也移出核心**：`00` §6 的表述是「v1 的学习模块采用一章一会话」，而不是「核心规定一章一会话」。

### 2.4 内容改版检测（不做成启动时全量比对）

v1 写的是「启动时比对 `chapterTitle`」，这需要把**所有有线程的册**全部拉下来解析，与 `03` §2.3 的「不解析正文」和「首屏 ≤ 2 秒」直接冲突。

**改为「打开该册时比对」**：用户打开某一册时，该册正文本来就要加载；此时比对每个线程 `binding.chapterTitle` 与当前同 `chapterIndex` 的章标题。不一致则写 `staleAt`，UI 在线程上显示「内容已更新」——**不静默错位**。

未打开过的册不做检测（没有成本，也没有必要）。

## 3. 划词引用

> **归属**：`QuoteRef` 属于 **`plugins/study`**，不属于阅读器，也不存在于静态网页版。它的唯一用途是把「用户在读哪一段」表达给模型——在没有 AI 的场合没有意义。阅读器只提供组装它所需的导航原语（`03` §9.4）。

```ts
type QuoteRef = {
  courseId: CourseId
  documentId: DocumentId
  chapterIndex: number       // 所在章
  chapterTitle: string
  sectionPath: string[]      // ["章标题", "节标题", "小节标题"]，缺失层级则更短
  /** 可选：仅本次解析内有效，**是提示不是依据**（规则见下表） */
  blockId?: string           // 形如 "3-27"（章序号-块序号）
  text: string               // 引用原文（持久化；这是跨会话可读的依据）
}
```

**`QuoteRef` 作为附件进入核心时，整体放在 `MessageAttachment.data` 里**（§2.1）——核心不认这个类型，只存不透明的 `{ kind: 'quote', data }`。

**关键设计：`blockId` 不是稳定标识。** 完整规则（与 `03` §9.1 一致，单一真相源在那里）：

| 用途 | 用哪个字段 |
|---|---|
| 本次会话内滚动跳回原文 | `blockId` |
| 跨会话 / 改版后展示出处 | `sectionPath` + `text` |
| 送给模型 | `chapterTitle` + `sectionPath` + `text` |

**引用送进模型的载荷形态**（作为普通 user 消息的一部分，绝不进前缀区）：

```
用户正在阅读《课程名》的《册名》整册，当前在第 N 章《章名》。
正在引用这一节（章 › 节 › 小节）的内容：

> 引用原文…

任务：<技能指令或用户自由输入>
```

## 4. 持久化（IndexedDB）

机器状态走 `StorePort`。**阅读器本身不写任何持久化**，它只发事件（`03` §9.3），由 app 层决定落库或丢弃——这正是静态版能「无记录」的实现方式。

| 表 | 键 | 索引 | 内容 | 静态版归属 |
|---|---|---|---|---|
| `settings` | `'app'` | — | `AppConfig`（**不含密钥**） | 内存 |
| `threads` | `id` | `scopeKey`（= `scope.key`）、`updatedAt` | `Thread` | 内存 |
| `turns` | `id` | `threadId` | `Turn` | 内存 |
| `items` | `id` | `threadId`、`turnId` | `Item` | 内存 |
| `progress` | `documentId` | `updatedAt` | `{ chapterIndex, blockId?, updatedAt }` | 内存 |
| `bookmarks` | `` `${documentId}:${chapterIndex}` `` | `documentId` | `{ note?: string, createdAt }` | 内存 |
| `favorites` | `courseId` | — | `{ createdAt }` | 内存 |
| `models` | `id` | — | `CustomModel`（**密钥不在此表**） | 内存 |
| `usage` | `id` | `createdAt`、`modelId` | `Usage`（成本与缓存） | 内存 |
| `contentCache` | `cacheKey` | `fetchedAt` | 单册正文（键 = 路径 + 大小） | **IndexedDB** |
| `remoteIndex` | `'tree'` | — | 远端文件树快照 + `fetchedAt` | **IndexedDB** |

**两条必须与 `03` §9.1 一致的规则**：

1. **`progress` 里的 `blockId` 是可选提示**，不是有效性依据。权威定位是 `chapterIndex`；提示失效时回退章首，**不报错**。
2. **内容缓存（`contentCache` / `remoteIndex`）在静态版也走 IndexedDB**——它们是「已读的册离线可读」的依据，不能因为"阉割记录"而丢掉。**只有会话与阅读状态是内存实现。**

**因此静态版需要两个 `StorePort` 实例**（`01` §3.1）：`store` = IndexedDB（只放上表最后两行），`ephemeral` = 内存实现（**其余九张表**）。这不是"一个端口两套语义"，是两个端口各司其职。

**选择 IndexedDB 而非 SQLite 的理由**：PC / 静态 / 安卓三处行为一致，**零原生代码、零迁移脚本**。代价是不像文件那样可以直接用编辑器查看——但机器状态本来就不是给编辑器看的（已明确不做摘录本，所以没有需要人读的产物）。

**已记录的风险**：IndexedDB 位于 WebView2 的用户数据目录，被第三方清理工具清掉是可能的。**丢失的内容只有会话与进度**（内容缓存可重建），最坏情况是重读，功能不受损。这是可接受的风险，不为此引入 SQLite。

## 5. 成本与缓存命中

```ts
type Usage = {
  id: string
  threadId: string
  turnId: string
  modelId: string
  protocol: LlmProtocol

  /** -1 表示**未知**（端点未报告 usage）——必须与 0 区分，见 04 §6.3 */
  prefixTokens: number
  cachedPrefixTokens: number
  inputTokens: number
  outputTokens: number

  /** 各稳定性分段的哈希。数组形式：同一 stability 可以有多个段（多个插件各贡献一段） */
  segmentFingerprints: { id: string; stability: ContextSegment['stability']; hash: string }[]

  firstTokenMs: number
  totalMs: number
  createdAt: number
}
```

`segmentFingerprints` 让「缓存没命中」这件事可被归因：是系统提示词变了、全册骨架抖了、还是换了章。**没有这个字段，「前缀稳定」就只能是一句祈祷。**

**它只证明"我们的前缀是稳定的"，不证明"供应商真的命中了"**——后者由 `cachedPrefixTokens` 表达，且常常是未知（`-1`）。两者必须分开呈现（`04` §6.3）。

## 6. 自定义模型

```ts
// LlmProtocol 在 01 §2.7 定义（唯一定义处），此处引用
type CustomModel = {
  id: string
  displayName: string
  protocol: LlmProtocol
  baseUrl: string
  modelName: string
  secretRef: string            // SecretPort 里的键名；密钥本身不在此表
  capabilities: ModelCapabilities
  enabled: boolean
  /** 端点要求的额外请求头（部分中转站需要） */
  extraHeaders?: Record<string, string>
}

type ModelCapabilities = {
  contextWindow: number
  maxOutputTokens?: number
  supportsToolCalls: boolean
  supportsStreaming: boolean
  supportsReasoning?: boolean
  /** 原样透传给请求体的额外旋钮（reasoning_effort / thinking 之类） */
  options?: Record<string, unknown>
}
```

**能力声明由用户可改**——这不是偷懒，是必要：中转站宣称的能力与实际行为经常不符（你现有的 provider 配置里就记录了 `supportsJsonSchemaOutput`、`supportsNativeWebSearch`、`optionSpecs.reasoningLevel` 这类**逐模型观测值**）。而这类字段**无法穷举**，所以除了几个布尔位之外，用 `options` 做一个"原样透传"的逃生口。

**能力声明被用于三件事**：上下文预算与超窗口降级（`04` §5.2.1）、功能可见性（不支持工具调用则隐藏跨章技能）、UI 表现（不支持流式则不显示逐字效果）。

**v1 不声明 `image` / `audio` / `pdf` 输入模态**：全库仅 2 处图片引用且都是坏引用（`03` §7），应用也没有任何输入音频/PDF 的入口。留一个恒为空的字段不如不要。

**密钥纪律**：`secretRef` 指向 `SecretPort`（PC 用 Tauri `stronghold`，口令流程见 `01` §3.2）。**配置文件、日志、错误信息、导出数据里永远不出现密钥明文**——这是对现有配置（`provider_config.json`、`omni-media/config.json` 的明文 `api_key`）的明确修正。

## 7. 应用配置

```ts
type AppConfig = {
  schemaVersion: number              // 迁移用。**唯一权威版本号就在这里**

  contentSource:
    | { kind: 'github'; owner: string; repo: string; ref: string }   // 默认
    | { kind: 'local'; path: string }                                // 可选

  profile: string                    // 只存键名；"键名 → 组合"的常量表在 packages/app（01 §5.1）

  plugins: Record<string, { enabled: boolean; settings?: unknown }>  // 以 id 为键的对象

  defaultModelId?: string            // 未设置 = 走 04 §5.5 的配置引导路径（**入口仍可见**）

  reader: {
    inlineMath: boolean              // 行内公式开关（默认 true）
    fontScale: number
    contentWidth: 'narrow' | 'comfortable' | 'wide'
    theme: 'system' | 'light' | 'dark'
  }

  updates: { autoCheck: boolean }
}
```

**不在此文件里的东西**：密钥（→ `SecretPort`）、会话与进度（→ 存储）、内容缓存（→ 缓存）。

## 8. 配置的权威位置（v1 有三个说法，定案）

| 形态 | `AppConfig` 存在哪 | 谁权威 |
|---|---|---|
| **PC** | **`<appDataDir>/config.json`**（走 `FsPort`） | `config.json`。理由：文件可备份、可手工修复、可被用户理解；这是分发给别人的软件的必要能力 |
| **静态网页** | IndexedDB 的 `settings` 表 | `settings` 表（没有 `FsPort`） |

**不做双向同步**：每个形态只读自己那一处。`schemaVersion` 只存在于 `AppConfig` 内（不再有"settings 行上的另一个字段"这种说法），迁移只对权威位置执行。

**PC 磁盘布局**：

```
<Tauri appDataDir>/
├─ config.json                 # AppConfig（无密钥）
├─ logs/                       # 本地日志（只在本机，绝不上传）
└─ cache/
   ├─ tree.json                # 远端文件树快照（PC 权威位置；静态版在 remoteIndex 表）
   └─ content/<hash>.md        # 单册正文缓存（键 = 路径 + 大小）
```

`logs/` 存在是为了**用户能自己排查问题**，不等于遥测——**本项目零遥测、零上报、零账号**。

**Tauri 权限前提**（否则上面这些目录写不进去）：`fs` 需要显式声明 `$APPDATA/**` 的**递归写** scope 与 `fs:allow-mkdir` 等权限——Tauri 2 默认只给 app 目录的递归**读**（`01` §3.2）。

## 9. 迁移

- `AppConfig.schemaVersion` 是**唯一**权威版本号
- 启动时若低于当前版本，按顺序执行迁移函数；迁移只做**加法与重命名**，不做破坏性删除
- 未知的更高版本 → 提示用户升级应用，**不尝试写入**（避免降级后数据错乱）
- 内容缓存的键含文件大小，因此**内容改版后旧缓存自然失效**，无需迁移
- `Thread.binding` 是开放对象，其内部结构变化由**插件自己**迁移（插件可以按 `schemaVersion` 判定并转换），核心不参与

## 10. 验收标准

| # | 标准 |
|---|---|
| 1 | 一次完整对话（含划词引用、工具调用、流式）落库后重开应用可完整复现 |
| 2 | `Usage.segmentFingerprints` 能区分「系统提示词变了」「全册骨架抖了」「换章了」三种缓存失效 |
| 3 | 端点不报告 usage 时，`prefixTokens` / `cachedPrefixTokens` 记 `-1`，成本面板显示「未知」而非「0%」 |
| 4 | 配置文件、日志、控制台输出中**搜不到任何密钥明文** |
| 5 | 内容仓库新增一册后，重启应用即可见（不需要任何迁移、不需要重新分配 id） |
| 6 | 手动把 `schemaVersion` 调高，应用拒绝写入并给出可读提示 |
| 7 | 清空 IndexedDB 后应用仍能正常启动与阅读（机器状态可丢，功能不可丢） |
| 8 | 同一份内容在 PC 版与静态网页版指向同一 `documentId`，缓存不互相污染 |
| 9 | **新增一个假想的第二插件，能用自己的 `scope.kind` 与 `binding` 建线程，且不改 `packages/agent` 与 `packages/plugin` 一行**（这是扩展性的验收，对应 `00` §1.3） |
| 10 | `progress` 的 `blockId` 指向一个不存在的块时，回退章首且不报错 |
| 11 | 静态版关掉重开：进度 / 书签 / 会话为空，但**已读过的册仍能离线打开**（内容缓存在 IndexedDB） |
